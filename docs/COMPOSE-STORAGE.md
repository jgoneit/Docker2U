# Compose 상태 표시와 저장소 탐색 v1

## 사용자 흐름

Compose 실행의 성공은 **명령 실행 완료**로 표시한다. 진행 창은 기존 컨테이너 목록
관측으로 현재 State·Health를 계속 갱신한다. 서비스에 복제본이 있으면 실제 이름과
컨테이너 ID별로 보여준다. Health 통과·시작 중·unhealthy·검사 미설정·확인 불가를
구별하고, 마지막 관측 시각과 오래된 목록 안내를 제공한다.

컨테이너가 없는 서비스는 컨테이너 확인 대기다. `exited`만으로 명령 실패를 추정하거나
프로젝트 전체를 준비 완료로 판정하지 않는다. Health 설정은 실제 컨테이너의
`Config.Healthcheck`에서 읽는다. `healthConfigured`는 `boolean | null`이며
검사 비활성화와 해석 불가를 구분한다.

각 실제 컨테이너의 로그·진단 버튼은 현재 세션의 정확한 full ID로 이동한다.
진행 창을 닫고 해당 탭에 포커스를 넘기며 실행 중인 Compose 작업은 유지한다.
오래된 목록·이전 세션·사라진 ID에서는 이동하지 않고 이름이 같은 새 컨테이너로
대체하지 않는다. 준비 완료 대기, `--wait`, HTTP/TCP 검사, pull/build 단계 파싱은 없다.

## 저장소 화면

- 프로젝트: 로그 · 저장소 · 이력
- 컨테이너: 로그 · 진단 · 접속 · 저장소 · 이력

저장소 탭은 실제 Engine이 반환한 마운트 종류, 원본 경로 또는 볼륨 이름, 내부 대상
경로와 읽기 전용 여부를 표시한다. 읽기 전용 값이 누락되면 확인 불가로 남긴다.
경로 복사는 앱의 기존 복사 피드백을 사용한다. 경로는 Engine 기준이며 Mac의 일반
폴더로 열 수 있다는 의미가 아니다.

프로젝트 화면은 실제 연결된 저장소별로 사용 서비스·컨테이너를 모은다. 등록 여부,
실행 상태, 목록 검색 필터와 관계없이 현재 연결의 전체 컨테이너를 대상으로 하므로
발견 프로젝트·중지 컨테이너·다른 프로젝트의 공유 사용자도 조회한다. 공유 사용자를
선택하면 정확한 컨테이너의 저장소 탭으로 이동하고 같은 연결을 강조한다.
등록했지만 아직 컨테이너가 없는 프로젝트에는 실제 연결 정보가 없다고 표시한다.
Compose 파일의 선언을 실제 연결로 대신하지 않는다.

조회 중, 실패, 일부 실패, 이전 결과, 마운트 없음은 서로 다른 상태다. 일부 조회에
실패했을 때 표시된 사용자 수를 전체 공유 사용자 수로 보장하지 않는다. volume의
이름이나 bind의 원본 경로를 확인할 수 없는 행은 공유 관계 확인 불가다.
탭을 오가도 기존 로그 필터·일시정지·위치 캐시와 키보드 탐색을 유지한다.

## 수집 계약

`get_mount_inventory(sessionId, refresh)`는 세션과 새로고침 여부만 받는 typed IPC다.
Core가 현재 목록의 전체 full ID를 선택하고 최대 100개씩 고정된 `inspect --format`
템플릿으로 조회한다. UI에서 경로, 명령, 컨테이너 ID를 입력받지 않는다.

응답은 세션 ID, 관측 시각, `complete | partial` 조회 범위, 컨테이너별 full ID와
조회 가능 여부, `type/source/destination/readOnly/volumeName`에 한정한다.
마운트 필드값을 확인할 수 없으면 null, 마운트 배열 자체를 해석하지 못하면 해당
컨테이너를 미확인으로 남긴다. 조회하지 못한 컨테이너를 빈 마운트로 바꾸지 않는다.

프런트의 전용 hook은 세션과 정렬된 ID 집합을 키로 메모리 캐시를 유지한다.
첫 진입·명시적 새로고침·ID 집합 변경 때 수집하고 목록 generation 변경만으로 전체
inspect를 반복하지 않는다. Core도 완전한 결과만 같은 세션·ID 집합에 재사용한다.
재연결은 캐시를 폐기하고 이전 응답을 거부한다. 조회 중 ID 집합이 바뀌면 이전 결과를
현재 전체 결과로 표시하지 않으며 새 ID의 미확인 상태를 보존한다.

마운트 수집은 한 번에 하나만 진행하고 기존 로그·자원 관측 예약을 점유하지 않는다.
CLI 수집 전체의 deadline은 30초이고 누적 출력과 최종 IPC 응답은 각각 8 MiB로
제한한다. 크기·시간 제한으로 미조회 항목이 남으면 공유 없음으로 판정하지 않는다.

## 공유 판단과 제외 범위

같은 연결의 volume은 정확한 볼륨 이름으로, bind는 Engine이 반환한 정확한 원본
문자열로 묶는다. tmpfs는 각 컨테이너에 속한다. 경로 상하위 관계나 심볼릭 링크를
검사하지 않고 이름 모양으로 익명 볼륨 여부를 추정하지 않는다.

파일 내용 열람·편집, Finder 열기, 볼륨 생성·삭제·백업·용량 계산은 제공하지 않는다.
이미지·코드 변경 반영, 터미널, 디스크 분석, 알림은 이 변경에 포함하지 않는다.

검증 범위와 환경 제한은 [이번 검증 기록](COMPOSE-STORAGE-AUDIT.md)에 남긴다.
