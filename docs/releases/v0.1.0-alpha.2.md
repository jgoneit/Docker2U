# Docker2U 0.1.0-alpha.2

로컬 컨테이너의 상태를 살펴보고, 문제가 생긴 시점의 기록에서 현재 점검으로 이어가는
macOS Apple Silicon용 테스트 릴리스입니다.

## 이번 버전에서 할 수 있는 일

- **프로젝트와 컨테이너를 한 화면에서 확인**: 트리 탐색, 실시간 로그, CPU·메모리와 상태 이력을 함께 확인합니다.
- **사건이 발생한 시점을 따라가기**: Compose와 독립 컨테이너의 사건에서 전후 로그·자원을 확인하고, 현재 진단이나 터미널을 방문한 뒤 같은 사건으로 돌아갑니다.
- **컨테이너 안에서 직접 점검**: `/bin/sh` 또는 `/bin/bash`를 명시적으로 연결합니다. 화면을 이동해도 세션과 입력·출력을 유지합니다. 탭을 여는 것만으로 셸이 실행되지는 않습니다.
- **Compose 작업과 상태 확인**: 등록한 프로젝트의 실행·중지, 선택한 서비스의 Apply, 서비스 상태와 마운트 정보를 확인합니다.
- **이미지 내보내기**: 컨테이너가 사용하는 이미지를 tar 파일로 내보냅니다.
- **읽기 편한 화면**: 한국어·영어, 시스템·라이트·다크 테마, 일관된 선택 컨트롤을 제공합니다.

삭제된 독립 컨테이너의 ID 필터와 기록 접근을 보완했고, 이력 페이지를 바꿀 때 이전 사건이
남지 않도록 수정했습니다. HTML 테스트의 CodeQL 지적과 배포 관련 의존성 보안 권고도 처리했습니다.

## 설치와 준비물

1. macOS 14 이상인 Apple Silicon Mac을 준비합니다. Intel Mac과 Windows는 이 배포의 대상이 아닙니다.
2. Docker CLI와 실행 중인 로컬 Linux Engine을 별도로 준비합니다. Docker2U는 런타임이나 VM을 설치·실행하지 않습니다.
3. `Docker2U_0.1.0-alpha.2_aarch64.dmg`를 열고 Docker2U를 Applications로 복사한 뒤 실행합니다.
4. 앱이 표시하는 연결 대상을 확인하고 프로젝트 또는 컨테이너를 선택합니다.

앱은 **ad-hoc 서명한 프리릴리스**이며 Apple Developer ID 서명·공증을 받지 않았습니다.
인터넷에서 내려받은 앱의 첫 실행은 macOS가 차단할 수 있습니다.
[설치 안내](https://github.com/jgoneit/Docker2U/blob/main/docs/INSTALL.md)를 참고하세요.
macOS 14+는 허용 범위이며 모든 OS·런타임 조합에서 검증했다는 뜻은 아닙니다.

## 사용 전에 알아두세요

- Start·Stop·Restart·Compose Apply와 터미널 명령은 실제 컨테이너에 영향을 줍니다.
- 터미널 연결 해제가 컨테이너 내부에서 실행 중인 명령의 종료를 보장하지 않습니다.
- 로그·자원·사건 기록은 앱 세션과 보관 한도 안에서 유지됩니다. 재연결·앱 종료 이후의 영구 기록은 제공하지 않습니다.
- 원격 TCP·SSH Engine, Windows·Intel Mac과 자동 업데이트는 지원하지 않습니다.
- 이 릴리스의 검증은 기록한 후보·플랫폼·시나리오에 한정됩니다. 공증이나 깨끗한 Mac에서의 Gatekeeper 인증을 의미하지 않습니다.

## 배포 파일과 무결성

DMG와 함께 `BUILD-INFO.json`, `DEPENDENCIES.json`, `THIRD_PARTY_NOTICES.txt`,
`RELEASE-NOTES.md`, `SHA256SUMS`를 제공합니다. BUILD-INFO에는 소스와 배포물의 대응을 기록합니다.
같은 폴더에서 다음과 같이 다운로드 파일의 체크섬을 확인할 수 있습니다.

```sh
shasum -a 256 -c SHA256SUMS
```

macOS 대상 의존성 검사와 남은 유지보수 경고는 [보안 검사 기록](https://github.com/jgoneit/Docker2U/blob/main/docs/releases/alpha2-dependency-audit.md)에 정리했습니다.
