# 컨테이너 터미널 v1

실행 중인 Compose·독립 컨테이너의 상세에서 **터미널** 탭을 열고 **연결**을
누르면 해당 컨테이너 안에서 대화형 셸을 시작한다. 기본은 `/bin/sh`이며
`/bin/bash`를 선택할 수 있다. 탭 이동이나 사건의 **현재 터미널** 버튼은 셸을
자동 실행하지 않는다. 셸이 없는 이미지에서는 오류를 확인하고 다른 셸을 선택한다.

## 화면과 수명

- 컨테이너마다 터미널 하나를 유지한다. 다른 컨테이너나 상세 탭으로 이동해도
  셸·출력·커서·스크롤을 유지한다. 언어·테마 변경은 새 연결을 만들지 않는다.
- 연결 중·연결됨·종료·연결 끊김·실패를 구분한다. 정상 종료 후에도 출력은 남는다.
- **연결 끊기**는 Docker와의 통신을 닫는다. 실행 중인 명령의 종료를 보장하지
  않는다. 셸에서 명령을 중단하거나 종료하려면 Ctrl+C, `exit` 등을 사용한다.
- **닫기**는 보관된 터미널과 출력을 제거하고 연결을 닫는다. 최대 8개를 보관하며,
  한도에 도달하면 기존 터미널을 명시적으로 닫아야 한다. 자동으로 다른 세션을
  종료하지 않는다. 스크롤백은 세션당 2,000줄이다.
- 일반 목록 새로고침은 같은 전체 ID의 연결을 유지한다. Engine 재연결·앱 종료는
  전체 연결을 정리한다. 컨테이너가 사라지거나 실행할 수 없는 상태가 되면 그
  연결을 정리하고, 이름이 같은 새 컨테이너로 옮기지 않는다.
- 컨테이너 정지·재시작과 Compose 재생성은 대상 컨테이너의 터미널 연결을
  정리한다. 다른 컨테이너의 터미널이나 읽기 전용 조회는 계속 사용할 수 있다.

## 연결 계약

Rust Core는 시작 요청의 session ID·현재 목록 generation·opaque handle을 검증하고,
정확한 전체 컨테이너 ID에 새 terminal ID를 묶는다. 이후 입력·크기 변경·출력
확인·연결 해제는 이 terminal ID를 사용한다. 일반 목록 갱신으로 generation이
바뀌어도 이미 열린 터미널의 대상은 바뀌지 않는다.

Docker exec는 세션에 고정된 로컬 Unix socket과 Engine identity를 사용한다.
컨테이너의 기본 사용자와 작업 디렉터리를 상속하고, `TERM=xterm-256color`와
대화형 TTY를 사용한다. 호스트 셸·임의 실행 파일·Docker 인자·endpoint를 받는
범용 실행 IPC는 제공하지 않는다. 원래의 읽기 전용 Engine API와 터미널 API를
분리하며, 실패하거나 결과가 불확실한 exec·입력을 자동 재시도하지 않는다.

출력은 ANSI·UTF-8 원본 바이트를 Tauri Channel로 전송한다. 최대 16 KiB 청크,
세션별 최대 256 KiB 미처리 출력을 허용한다. xterm이 처리한 범위만 확인하며,
상한에서는 Engine 소켓 읽기를 멈춘다. 입력·취소는 별도 경로로 처리해 많은
출력 중에도 Ctrl+C와 연결 해제를 처리한다. 숨겨진 터미널도 출력을 처리하지만
크기가 0인 화면 정보를 Engine에 전달하지 않는다.

터미널 입출력은 앱 세션 메모리에만 존재하며 일반 로그 보관·진단 복사에 포함하지
않는다. 터미널에서 출력한 URL·제어 문자열로 호스트 앱을 실행하거나 클립보드를
변경하지 않는다. 컨테이너에 설정된 마운트·네트워크·사용자 권한은 그대로 적용된다.

## 검증 경계

자동 검사, 합성 브라우저·네이티브 fixture, 실제 Engine 명령 입출력과 설치된 앱
확인은 각각 구분해 기록한다. 합성 셸 응답은 실제 컨테이너 명령 실행 증거가 아니다.
