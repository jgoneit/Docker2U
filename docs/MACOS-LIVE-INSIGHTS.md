# macOS 로그·프로젝트·자원 관찰

2026-09-07 승인 범위. 기준 소스는 `89ace30`이며 작업은 별도 checkout
`.cache/macos-live-insights`의 `codex/macos-live-insights`에서 수행한다.
기존 checkout과 로컬 앱은 자동으로 삭제하지 않는다.

## 사용 흐름

- 목록은 Compose `com.docker.compose.project` / `com.docker.compose.service`
  두 라벨로만 구분한다. 프로젝트명·컨테이너명 순으로 정렬하며 라벨이 없는 대상은
  **프로젝트 없음**에 둔다. 검색은 프로젝트·서비스 이름을 포함한다.
- 프로젝트 헤더의 개수와 전체 선택은 현재 검색·상태·프로젝트 필터 결과를 따른다.
  필터를 바꾸면 체크 선택과 숨겨진 상세 선택을 해제한다. 목록 갱신으로 현재
  프로젝트가 사라지면 전체 프로젝트로 필터를 복구한다.
- 실행 중·일시정지·재시작 중인 대상을 선택하면 최근 300줄과 이후 출력을
  `container logs --follow --tail 300 --timestamps` 한 번으로 받는다.
  created/exited/dead 상태에서는 기존 최근 로그 조회를 사용한다.
- **화면 일시정지** 또는 검색 열기는 표시만 고정한다. 수신은 계속된다.
  검색을 닫으면 수동 일시정지가 아닌 경우 최신 내용으로 복귀한다.
  위로 스크롤하면 자동 이동을 멈추며 최신 위치 버튼으로 다시 따라간다.
- **비우기**는 수신까지 종료한다. 다시 조회하거나 다른 대상을 선택할 때까지
  빈 화면을 유지한다. 수신 오류 뒤에도 이미 받은 본문은 남긴다.
- 목록과 상세의 CPU·메모리는 같은 관측값을 사용한다. 현재 필터에 포함된 실행 중
  컨테이너를 즉시 조회하고 완료 후 5초 뒤 다시 조회한다. CPU는 100%를 넘을 수
  있으며 미수집·중지는 `—`, 실패 후 남긴 값은 **오래된 값**이다.
  메모리 사용량/한도는 Docker CLI 표시 그대로이며 Engine/VM의 한도는 Mac 전체
  물리 메모리를 의미하지 않는다. 목록 자체는 자동 갱신하지 않는다.

## 실행과 데이터 경계

### 정보 배치

기본 화면 위쪽에는 가로폭을 쓰는 컨테이너 표를 둔다. 프로젝트별로 묶인 표에서
이름·상태·CPU·메모리·포트를 같은 행에서 비교하고 작업 대상 체크를 선택한다.
아래쪽에는 선택한 컨테이너의 복구 동작과 로그를 둔다. 이미지, 전체 ID와 복사,
프로젝트·서비스, 상세 자원값과 목록/자원 관측 시각, 메모리 한도 설명은
**컨테이너 정보**에서 펼쳐 본다. 오래된 값·연결 차단·조작 중·로그 유실 경고는
접기 밖에 유지한다.

목록과 로그 사이의 경계를 위아래로 끌어 로그 높이를 조절한다. 키보드 초점을
둔 경계에서 위/아래 방향키는 20px씩, Home/End는 현재 허용 범위의 최소/최대
높이로 이동한다. 두 번 클릭하면 초기 300px 기준으로 돌아간다. 작은 창에서는
목록 공간을 남기도록 높이를 제한하며, 실제 최소·최대·현재 높이를 접근성 속성으로
알린다. 높이는 현재 앱 세션에서만 유지하며 설정 변경과 분할 조절로 로그를 다시
조회하거나 선택을 초기화하지 않는다. 미니 창과 항상 위 기능은 이번 범위가 아니다.
패널을 낮게 줄이거나 정보·검색·경고가 함께 열리면 로그 본문은 최소 80px를 남기고
하단 패널 안에서 스크롤해 주변 정보와 도구에 접근한다.

로그 도구막대는 일시정지/재개를 텍스트로 두고 조회·검색·확대를 이름과 설명이
있는 아이콘으로 표시한다. 복사·비우기는 도구막대의 복사·휴지통 아이콘으로
직접 실행하며 접근 가능한 이름과 설명을 제공한다. 최신 위치 이동은
로그를 위로 스크롤했을 때 표시한다. 연결 도움말과 endpoint는 환경 진단에서,
연결 상태는 상단에서 확인한다. 이 접기와 분할 조절은 로그 컴포넌트·수신·검색
상태를 새로 만들지 않는다. 네이티브 fixture도 아이콘·컨테이너 정보의
현재 접근 경로를 사용한다.

상단과 빈 화면에는 기존 Docker2U 앱 로고를 표시한다. 로고 계열의 파란색은
활성 필터·새로고침·선택한 행과 복사 성공에 사용하고, 실행·오류·주의 상태는
각 의미의 색과 텍스트를 유지한다. 색상 역할과 다크 모드 대비를 나누는 방향은
[토스의 컬러 시스템 설명](https://toss.tech/article/43385)을 참고했다.

복사와 로그 화면 비우기 결과는 하단 상태바 오른쪽의 텍스트로 표시한다. 별도
알림 카드·아이콘·테두리는 두지 않는다. 복사 성공에는 은은한 파란색, 수동 비우기와
복사 실패에는 은은한 붉은색이 상태바에 잠시 들어온다. 약 2초 뒤 색 강조가 사라지고
일반 색상의 마지막 작업 문구만 다음 복사·비우기 결과가 나올 때까지 남는다.
반복 실행하면 색 강조 시간을 다시 시작하며, 비우기 문구는 사용자가 휴지통 버튼을
눌렀을 때만 표시한다. 대상 선택·재연결은 이미 표시한 마지막 작업 문구를 지우지 않는다.
확대 로그에서도 같은 표현을 사용하고 하단 공간을 항상 확보해 작업 결과가 로그
영역 높이를 바꾸지 않는다.
최근 복사 또는 비우기보다 늦게 도착한 이전 복사 결과가 새 알림을 덮어쓰지 않는다.
언어·테마 변경은 색 강조의 남은 시간과 로그 상태를 유지한다. 모션 감소 설정에서는
색을 부드럽게 전환하는 애니메이션을 생략하고 같은 시간 동안 정적인 강조만 표시한다.

버튼의 기본 상태는 면색·아이콘·텍스트로 구분하며 밝은 외곽선을 상시 표시하지
않는다. 선택·실행·중지·재시작의 의미 색은 유지하고 키보드 초점에는 별도의
뚜렷한 외곽선을 표시한다.

검색창과 프로젝트 선택은 높이·둥근 모서리·부드러운 배경을 맞춘다. 프로젝트는
폴더 아이콘과 선택값을 한 묶음으로 표시하며 긴 이름은 도움말에서도 확인할 수 있다.
선택 팝업과 키보드 탐색은 기본 select 동작을 사용하고, 검색·선택에 초점을 두면
파란 강조를 표시한다. 로그 검색창에도 같은 입력 스타일을 사용한다.

이번 배치의 실제 WKWebView/브라우저 시각 검증은 앱 접근 거절로 미수행이다.
DOM·접기·접근 가능한 버튼 이름·설정 보존 검사와 패키지 빌드는 시각 검증과 구분한다.

분할 화면용 브라우저 검사는 1024×680/1280×800의 한국어·영어, 밝은/어두운
테마 조합과 기존 1600×1000 표본에 편성했다. 포인터 드래그, 방향키·Home/End,
두 번 클릭 초기화, 높이 범위와 실제 배치, 일시정지·검색·스크롤·수신 시각 DOM,
설정·창 크기 변경 전후 동일 수신을 검사하도록 작성했다. `playwright test --list`의
162개 탐색과 브라우저 테스트 TypeScript 검사는 통과했지만 새 화면 테스트 본문은
실행하지 않았다. 이전 접근 거절을 다른 브라우저·CDP·실행 옵션으로 우회하지 않았다.

새 native **pane-resize** probe는 실제 IPC 수신 중 일시정지한 검색 화면에서
키보드로 높이를 변경하고 되돌린다. 보고서 검증기는 실제 pane/list 높이의 반대 방향
변화와 원복, 같은 follow PID의 추가 출력, 직렬 read 및 화면 보존을 함께 요구한다.
준비 조건 단위 검사 8개와 native Evidence 검사 13개는 직접 실행해 통과했다.
이는 probe와 검증기의 코드 검증이며, 실제 WKWebView 키보드·드래그 성공 증거는 아니다.
기존 Engine 및 이전 후보의 검증 수치는 아래에 별도 보존한다.

### Engine과 프로세스

CLI가 선택한 로컬 Linux Engine을 connect/Reconnect 때만 해석하고 endpoint와
Engine identity를 고정한다. 프런트엔드는 session/generation/opaque handle만
전달한다. 새 Tauri 명령은 명시적 command·capability·permission 목록에 포함한다.
임의 명령, endpoint, Compose 경로, 환경 변수와 전체 라벨은 전달하지 않는다.

앱당 follow 프로세스는 하나다. 시작 예약을 Engine 검증보다 먼저 수행하고 실제
spawn 직전에 예약·세션·generation·handle을 다시 검사한다. 정상 목록 갱신으로
handle이 바뀌어도 session/full ID/stream ID가 같은 수신은 유지한다. 정리와 join은
Core 상태 잠금 밖에서 수행한다. 프로세스 그룹·정제된 환경·전체 8개 자식 한도를
공유하며 stdout/stderr를 모두 로그로 취급한다. stderr 출력만으로 실패하지 않는다.

Core는 검증 완료 후 5초 간격으로 Engine을 다시 검사한다. 이전 스트림의 결과로
새 세션을 무효화하지 않는다. 프런트엔드는 250ms 간격으로 네이티브 대기 버퍼를
직렬 읽고, 오래된 응답을 버리며 늦게 완료된 start가 만든 스트림도 종료한다.
대상 변경·제거, 비우기, 재연결·세션 무효화, 앱 종료가 자신이 만든 프로세스를 정리한다.
자연 종료는 반복 재실행하지 않는다. 일반 목록 갱신은 같은 full ID의 진행 중인
수신을 유지한다. 선택한 대상의 Restart 성공과 정상 목록 재조회를 확인한 경우
현재 handle로 수신을 정확히 한 번 교체하며 최근 로그를 대체하여 중복을 막는다.
이렇게 하면 이전 follow의 종료가 늦어도 복구가 누락되거나, 재시작 의도가 남아
나중의 자연 종료를 다시 실행하지 않는다. 비우기·다른 대상 조작·실패에는 이
강제 교체를 적용하지 않는다.

아직 follow 시작 검증이 끝나기 전에 목록 generation이 바뀌면 Core가 오래된
handle의 시작을 거부한다. 이 경우 이미 열린 수신의 유지와 달리 로그 오류 상태가
남을 수 있으며 **다시 조회**로 현재 목록의 handle을 사용한다. 자동 시작 재시도는 없다.

네이티브 대기 버퍼, 최신 프런트엔드 본문, 일시정지한 본문 각각 최대 **2 MiB**다.
UTF-8와 ANSI는 분할 입력을 처리하며 불완전 제어문자 상태도 제한한다. 오래된
내용이 제거되면 안내한다. 이 기능은 전체 로그 보관이나 내보내기를 보장하지 않는다.

통계는 explicit full ID를 최대 100개씩 순차 조회한다. 빈 대상이면 명령을 실행하지
않는다. 명령당 10초, 사전 Engine 검증 이후 전체 수집 15초 한도를 적용한다.
실패·누락·시간 초과 묶음은 수집 불가이고 개별 컨테이너 재시도는 없다. 요청 밖 ID,
중복 ID와 잘못된 JSON/수치는 수락하지 않는다. 창 숨김·재연결·목록 갱신·조작 중에는
새 조회를 멈추고, 이전 요청이 끝난 뒤 유효한 목록에서 재개한다. 일반 통계 오류는
통계만 오래된 표시로 만들며 연결 무효화 오류만 재연결·조작 차단으로 전달한다.

Windows, 사용자 지정 프로젝트, Compose 실행·편집, 프로젝트 자원 합산,
통계 이력·알림·네트워크 모니터링, 원격 게시·Release는 이번 범위가 아니다.

## 검증 경계

2026-09-07 권한 변경 후 root 실행에서 임시 파일 생성·삭제, Unix socket bind,
localhost TCP bind와 `desktop-linux` Docker Engine 접속을 확인했다.
기존 child 세션은 이전 권한을 유지했으므로 소켓·Engine 검증은 root에서 수행했다.

- **Rust 전체:** 71개 통과, 실패 0개. 실제 Engine opt-in 4개는 기본 실행에서
  제외된다. 이 중 신규 실제 Engine 검사는 아래처럼 정확한 테스트 이름을 지정하여
  별도 실행했다.
- **실제 Engine:** `docker::tests::insights::live::real_live_insights_smoke` 1개 통과.
  `Core::default()`가 선택한 현재 Engine에 고유 이름·소유 label이 있는 임시
  busybox 컨테이너 하나만 생성했다. Compose 라벨, stdout/stderr follow,
  이후 생성된 tick 수신, Refresh 후 같은 full ID의 수신 유지, Core Start/Restart,
  재시작 후 새 boot 로그 및 통계 재구독을 검증했다.
  Core CPU 0.79% / CLI 0.60%, 메모리 2.52MiB / 64MiB와
  2.629MiB / 64MiB를 비교했다. 순차 관측이므로 CPU·사용량의 완전 일치를
  요구하지 않고 응답의 full ID·형식·메모리 한도 및 허용 오차를 검사했다.
  endpoint identity·full ID·이름·소유 label 확인 후 해당 컨테이너만 제거했고,
  소유 label로 남은 대상이 0개임을 확인했다. 기존 업무 컨테이너는 조작하지 않았다.
- **Python native fixture:** 새 보고서 검증 5건을 포함한 최종 22/22 통과.
  새 UI probe 보고서 검사는 frontend probe와 검증기 계약을 함께 보강한다.
  CLI 성공 기록, 같은 프로세스의 follow 출력·종료, inventory 조회를 함께 요구하여
  임의 UI 보고서만으로 새 기능 검증을 통과시키지 않는다.

- **브라우저:** 153개(새 기능 36개 포함)를 실행했지만 Chromium 시작 단계의

## 로컬 패키지와 되돌리기

아래 설치·실행 기록은 목록/분할 화면 변경 전 후보의 기록이다. 새 분할 화면
후보의 Seal 완료와 설치·실행 결과는 아직 이 문서의 완료 근거에 포함하지 않는다.

`pnpm native:build --ci --no-sign -- --locked`로 macOS14+ Apple Silicon `.app`
빌드가 완료됐다. 도구 체인의 rust-objcopy는 libLLVM 경로 누락 경고를 냈지만
release 컴파일과 번들은 exit0으로 생성됐다. 최종 복사본의 실행 파일 SHA-256을
빌드 원본과 대조했다. Developer ID 서명·공증·Gatekeeper 검증은 수행하지 않았다. 네이티브 fixture는
별도 bundle identifier·경로의 앱으로 빌드하며 실제 설치 앱과 구분한다.

- 설치 앱: `/Applications/Docker2U.app`
- workspace 복사본: `/Users/jgoneit/project/Docker2U/.local-apps/Docker2U.app`
- 이전 앱: `/Users/jgoneit/project/Docker2U/.local-apps/Docker2U.previous-20260907-211616.app`
- UI 정리 전 세 기능 구현본: `/Users/jgoneit/project/Docker2U/.local-apps/Docker2U.before-ui-cleanup-20260907.app`
- 실행 요청: `open -n`이 macOS `-10827`(kLSNoExecutableErr)을 반환했다. 실행 파일은
  복사·해시 대조됐지만, 이 실행 환경에서 GUI를 열 수 있었는지는 확인하지 못했다.
- 권한 변경 후 `/Applications/Docker2U.app`에 설치하고 실행 파일·Info.plist·아이콘을
  workspace 복사본과 SHA-256 대조했다.
- 복구하려면 새 앱을 닫고 위 백업 `.app`을 다시 사용한다. 소스 변경은 별도 checkout에
  있으므로 원래 release checkout을 사용하면 이전 구현으로 복구할 수 있다.

실제 사용 완료 기준에는 허용된 Host UI에서 브라우저·WKWebView 가독성/포커스와
GUI 재시작 후 자동 회복 확인이 남아 있다. Core 소켓 fixture 및 실제 Engine의
로그·통계·재시작·재구독은 위의 별도 검증에서 통과했다.
