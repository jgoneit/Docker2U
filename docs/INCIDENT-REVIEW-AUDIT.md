# 사건 기록 확인 v1 검증 기록

## 기준과 구현

- 기준: `origin/main`의 `3f26db6a4978cf6bc640f390f1265884ddce0010`.
- 작업 브랜치: `codex/incident-review-v1`.
- Compose 사건 행 펼침 → 사건 전후 로그·자원 → 현재 상세 → 같은 사건 복귀.
- 로그 조회는 세션·프로젝트·컨테이너 전체 ID·시간 구간으로 제한한다.
  조회가 수집 설정을 바꾸지 않으며, 일반 로그의 검색·일시정지·위치를 유지한다.
- 검토에서 재연결 후 캐시 재유입, 삭제된 컨테이너의 프로젝트 이력 복귀,
  만료된 사건을 닫을 때 포커스 손실을 재현하고 회귀 테스트와 함께 수정했다.
- 보관 만료 중 페이지 이동은 행 ID 경계를 확인한다. 경계가 사라지면 기존
  화면을 유지하고 안내한다. 새로고침 실패도 이전 로그·조회 상한·자원 표본을
  유지하며, 실패 뒤 구간 변경이 최신 로그를 섞지 않는지 검사했다.

## 검증 한계

- 메모리 보관 만료는 계속 적용된다. 조회 결과 유지는 영구 보존이 아니다.
- 잘림·수집 공백은 프로젝트 전체 집계다. 사건 원인이나 정확한 손실 시각을
  자동으로 판정하지 않는다.
- Native fixture는 합성 Docker CLI/Engine 응답과 실제 Rust IPC·WKWebView를
  사용한다. 실제 Engine 조회, 설치 앱 검증, 서명·공증과 별개다.
- PR 생성, 배포용 서명·공증은 수행하지 않았다. 후속 요청으로 진행한
  로컬 설치와 ad-hoc 서명 검증은 아래에 따로 기록한다.
