# 독립 컨테이너 통합 로그와 사건 확인

왼쪽 **독립 컨테이너** 그룹에서 독립 컨테이너 전체의 통합 로그와 이력을 확인한다.
행 선택은 그룹 화면을 열고, 화살표는 자식 목록만 접거나 펼친다.

## 수집과 화면 상태

- 그룹 또는 독립 컨테이너를 선택하면 독립 범위 전체의 최근 로그를 가져온 뒤
  백그라운드에서 수집한다. 그룹을 방문하기 전부터 모든 로그가 수집된다는 뜻은 아니다.
- 그룹↔자식↔다른 독립 컨테이너↔상세 탭 이동은 표시 대상만 바꾼다. Compose
  프로젝트로 이동하면 활성 수집 범위를 바꾸고 기존 기록은 보관 한도 안에서 유지한다.
- 한 수집 관리자에서 최대 64개를 동시에 수집한다. 64개를 넘으면 사용자가
  대상을 선택해야 한다. 자동 선택에는 새 컨테이너가 합류하지만, 명시 선택은
  전체 ID에 고정하며 같은 이름으로 재생성된 컨테이너를 대신 선택하지 않는다.
- 그룹과 각 컨테이너의 검색어·일시정지·비운 로그 경계·읽던 위치를 각각 유지한다.
  컨테이너 필터에는 이름·짧은 ID·삭제 여부를 표시하며 필터 값은 전체 ID다.
  삭제된 ID를 선택한 필터도 Compose 왕복 후 유지한다. 보관 페이지에서 확인한
  삭제 항목을 필터로 선택할 수 있으며, 같은 이름의 새 ID를 대신 조회하지 않는다.
- 화면 일시정지와 로그 비우기는 표시 상태다. 다른 화면의 보관 기록이나
  백그라운드 수집을 지우거나 중단하지 않는다.
- 이전 개별 실시간 로그와 중복 수집하지 않는다. Compose와 독립 범위가 기존
  전역 byte·행 수·시간·페이지 한도를 공유한다.

## 사건에서 현재 점검으로

1. 그룹 또는 개별 컨테이너 **이력**의 사건을 선택한다.
2. 해당 행 아래에서 같은 전체 ID의 당시 로그와 CPU·메모리를 확인한다.
3. 전후 2분을 기본으로 1분·5분을 선택하거나 보관 로그 페이지를 이동한다.
4. **현재 진단·접속·저장소·터미널**로 현재 컨테이너를 점검한다. 터미널은
   사용자가 **연결**을 누르기 전까지 셸을 실행하지 않는다.
5. **사건으로 돌아가기**로 사건·구간·이력 위치·포커스를 복원한다.

사건의 최초 조회 결과를 유지하며 **사건 기록 새로고침**으로 갱신한다. 사건
조회는 수집 범위를 변경하지 않는다. 현재 정보는 사건 당시 기록과 구분한다.
이력 페이지를 바꾸면 기존 선택 사건을 닫아 이전 페이지의 복귀 상태를 남기지 않는다.

삭제된 컨테이너의 사건도 보관된 전체 ID로 조회한다. 현재 정보 버튼은 원래 ID가
목록에 있을 때만 사용할 수 있다. 현재 독립 컨테이너가 0개여도 보관 사건이 있으면
그룹 이력에 접근할 수 있다. 같은 이름의 새 컨테이너 로그를 이전 사건에 섞지 않는다.
사건 스트림이 삭제를 놓치더라도 이 세션에서 독립 로그 수집을 시작했다면 빈 그룹을
유지한다. 보관 로그로 돌아갈 수 있도록 한 것으로, 보관 한도나 만료를 연장하지 않는다.

## 조회 경계

내부 보관 범위는 `Project { name } | Standalone`이다. 독립 범위를 예약된
프로젝트 문자열로 표현하지 않는다. 기존 프로젝트 configure/query 호출은 유지하고
독립 configure/query/retry를 추가한다. 세션·범위·전체 ID·사건 시각이 조회 대상을
고정한다. 재연결은 사건 상세·복귀·화면 캐시를 초기화하고 이전 응답을 폐기한다.

시간 없는 로그는 수신 시각을 사용하고 표시한다. 빈 조회는 **해당 구간에 보관된
로그 없음**으로 안내하며 보관 범위·잘림·만료·수집 공백 정보를 함께 보여준다.
관찰 표본이 없는 구간을 0으로 채우지 않는다. 보관 공백만으로 장애 원인을 단정하지
않으며, 앱을 닫은 뒤의 영구 기록·알림·디스크 분석은 제공하지 않는다.
