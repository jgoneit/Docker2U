# Compose 사건 기록 확인 v1

이력에서 Compose 컨테이너의 사건을 선택하면 그 행 아래에 보관 로그와 CPU·메모리
그래프를 펼친다. 기본 구간은 사건 전후 2분이며 1분·5분으로 바꿀 수 있다.
일반 로그의 검색어·일시정지·위치는 사건 조회와 분리한다.

## 화면과 데이터

- 한 사건만 펼친다. 사건 시각, 서비스, 컨테이너 이름과 정확한 ID를 표시한다.
- 처음 조회한 로그와 자원 표본을 유지한다. 구간 변경은 같은 조회 시점의 자료를
  사용하며 **사건 기록 새로고침**만 새 관찰 자료와 로그 상한을 가져온다.
- 로그는 사건에 가장 가까운 행을 중심으로 최대 160행씩 읽는다. 이전·다음으로
  구간을 탐색하고 시간 없는 행은 수신 시각이라고 표시한다.
- 그래프의 점선은 사건 시각이다. 표본 누락이나 15초를 넘는 관측 간격을 0으로
  채우거나 선으로 연결하지 않는다.
- **현재 진단·접속·저장소**는 사건 당시 스냅샷이 아니라 현재 컨테이너 정보다.
  **사건으로 돌아가기**는 선택 사건·구간·이력 위치와 포커스를 복원한다.
- 삭제·재생성 전 ID의 자료가 남으면 조회한다. 현재 목록에 그 ID가 없으면 현재
  정보 버튼을 비활성화한다. 이름이 같은 새 컨테이너로 대신 이동하지 않는다.
- 재연결은 사건 상세와 복귀 상태를 해제하며 이전 요청 결과를 사용하지 않는다.

## 조회 계약

기존 `query_project_logs`에 선택적인 `timeFrom`, `timeTo`, `anchorTime`을 추가한다.
RFC3339 시각을 받아 양끝을 포함한 구간으로 필터링하며, 잘못된 시각·역전 구간·
범위 밖 기준 시각은 거부한다. 시각 조건이 없는 호출의 기존 동작은 유지한다.
명시한 행 기준 또는 offset이 있으면 이를 우선하고, 없으면 기준 시각에 가까운
행 주위에서 시작한다. 정렬·경계 비교는 Core의 나노초 시각을 사용한다.

사건 조회는 프로젝트와 컨테이너 전체 ID를 필터링하고 기존 메모리 보관 자료만 읽는다.
수집 설정·현재 수집 프로젝트·Docker 상태는 변경하지 않는다. 최초 결과의
`maxSequence`를 후속 페이지의 `throughSequence`로 고정한다. 보관 만료는 계속
적용되므로 이 기능은 영구 스냅샷이나 디스크 기록이 아니다.

시간 조건이 있는 응답의 보관 구간은 시각 필터 적용 전 선택 컨테이너 자료의 범위다.
잘림·수집 공백 횟수는 기존 프로젝트 전체 집계이며 특정 사건의 원인이나 정확한
손실 시각으로 해석하지 않는다. 자료가 없으면 **해당 구간에 보관된 로그 없음**으로
안내한다. 미수집·정상적인 무출력·만료 중 무엇 때문인지 근거 없이 단정하지 않는다.

## 범위

Compose 프로젝트와 그 컨테이너만 사건 로그 연결을 제공한다. 독립 컨테이너의
기존 이력은 유지한다. 앱 세션과 기존 보관 상한을 사용하며 원격 Engine, 디스크
저장, 터미널, 알림, 자동 원인 판정은 추가하지 않는다.

## 검증

검사 결과와 검증 범위는 [검증 기록](INCIDENT-REVIEW-AUDIT.md)에 남긴다.
Native fixture의 합성 Health 사건은 실제 Docker 장애 재현 결과가 아니며
실제 Engine 읽기 검사는 기존 컨테이너를 변경하지 않는다.
